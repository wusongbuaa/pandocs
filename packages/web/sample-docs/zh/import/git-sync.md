---
title: Git 同步
---

让空间和 Git 仓库的一个目录双向保持一致。有人在浏览器里改页面，也有人改文件再推送，双方通常一分钟内就能拿到对方的内容。

空间管理员在空间的 **Git 同步**页面设置，需要仓库的 HTTPS 地址、分支，以及能读能推的访问令牌。目录留空表示整个仓库，目录以外的文件不会动。

:::warning

这个功能测试时连的是本机的 Git HTTP 服务，没有连过真实的 GitHub 或 GitLab。第一次使用时，建议先用测试仓库试试。

:::

## 页面和文件怎么对应

| 空间里 | 仓库里 |
| --- | --- |
| 页面 `guide/start` | `<目录>/guide/start.md` |
| 没有正文、只放子页面的页面 | 一个目录 |
| 图片 | `<目录>/assets/<hash>.<ext>` |
| 标题、顺序和标签 | `<目录>/.pandocs/pages.json` |

评论、修改建议、译文和谁能读什么都不在仓库里。受限页面也不进仓库，除非明确勾选。

## 两边都改了怎么办

| 仓库里 | 这里 | 结果 |
| --- | --- | --- |
| 文件改了 | 页面没改 | 页面生成新版本 |
| 文件改了 | 页面改了别处 | 合并两边的内容，再把结果推回去 |
| 文件改了 | 页面改了同一处 | 页面内容不变并推给仓库。文件的内容变成修改建议，由人决定，什么都不会丢 |
| 文件新增 | 没有这个页面 | 新页面 |
| 文件改名 | 不管有没有改 | 页面移动，评论还在，旧地址仍然有效 |
| 文件删除 | 页面没改 | 页面进回收站 |
| 文件删除 | 页面改了 | 页面留着，文件恢复 |

如果空间要求所有改动走[变更集](../collaboration/change-sets.md)，仓库来的内容会进一个变更集，等人合并。

## 不支持的

受保护分支（它直接往分支上推，托管方要求走合并请求时会失败并说明原因）、Git LFS、SSH 地址和密钥、子模块和符号链接。

Docker 镜像里已经带了 Git。其他方式部署时，服务器上要有 2.37 或更新版本的 `git`。
