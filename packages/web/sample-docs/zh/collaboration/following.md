## 关注

在页面上方点铃铛，可以关注这个页面，或者它所在的空间。之后有更新时：

- **通知中心**里会有提醒，右上角的铃铛能看到数量。
- 配置了邮件服务时也会发邮件。邮件在安静一分钟后才发，每人一封，不管改了多少页面。导入一千个页面不会变成一千封邮件。

@ 你的评论、回复你的评论、等你确认的修改建议也会进通知中心。

## Webhook

Webhook 把事件发到别的地方：给人看的群聊，或者你自己的系统。它只往外发，群里的机器人不能反过来操作文档。

空间管理员在空间的 **Webhook** 页面设置，站点管理员可以设全站的。

| 发到 | 地址从哪来 |
| --- | --- |
| 飞书或 Lark 群 | 群设置里添加自定义机器人 |
| Slack | 给频道添加的传入 Webhook |
| 企业微信群 | 群设置里添加群机器人 |
| 钉钉群 | 群设置里添加自定义机器人 |
| Microsoft Teams | 频道里收到 Webhook 请求时发帖的工作流 |
| 你自己的系统 | 你自己的地址，可以设密钥校验签名 |

群聊的消息会在事件发生约十秒后发出，把这段时间内的事情合成一条：最多十行，其余的给个数量。

受限页面默认不发，因为它们的标题和评论会跟着消息出去。

## 发给自己的系统

每个事件是一次 JSON 的 `POST`，请求头带事件名、投递 ID 和签名。

```json
{
  "event": "page.updated",
  "site": "https://docs.example.com",
  "space": { "slug": "handbook", "name": "手册" },
  "page": { "title": "退货政策", "path": "guides/returns", "url": "https://docs.example.com/handbook/guides/returns" },
  "actor": { "name": "小李", "kind": "user" },
  "revision": 12,
  "message": "延长退货期限"
}
```

失败后会在 1 分钟、5 分钟、30 分钟、2 小时和 6 小时后各重试一次。连续失败 50 次后 Webhook 会自动关闭。

事件和改动在同一个事务里记录，所以失败的改动不会发通知，成功的改动也不会因为服务器马上停了就丢掉通知。
