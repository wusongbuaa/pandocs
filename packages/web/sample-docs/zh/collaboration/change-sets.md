---
title: 变更集
---

改一个页面用修改建议就够了。要同时改好几个页面时用**变更集**：大家一起评审，要么全部生效，要么都不生效。

典型的场景是产品改名、接口升级，或者让智能体把一批页面改一遍。

## 流程

```mermaid
flowchart LR
  A[人或智能体新建变更集] --> B[往里加页面]
  B --> C[别人评审]
  C -->|要求修改| B
  C -->|批准| D[合并]
  D --> E[每个页面生成新版本]
```

- 变更集里的页面可以是新的全文、一个新页面，或者一次删除。
- 能评论的人都可以新建变更集，所以智能体也可以。
- **合并只能由人来做。** 合并在一个事务里完成：每个页面基于当前内容三方合并，只要有一个合并不了，就什么都不会改，并告诉你是哪个页面。
- 建错的变更集可以关闭，它会留在**已关闭**里；也可以删除，连同评审一起永久删掉。删除只有发起人、智能体所代表的那个人和空间管理员能做，并会记进空间的操作记录。已合并的变更集是页面历史的一部分，不能删除。

## 空间的规则

在空间的**变更集**页面可以设两条规则：

| 规则 | 作用 |
| --- | --- |
| 变更集需要的批准人数 | 不到这个人数不能合并 |
| 所有改动都走变更集 | 任何人都不能直接保存、移动、删除或恢复页面，管理员也一样，除非先改规则 |

翻译、标签和评论不受这些规则限制，因为它们不改变页面说的内容。

## 智能体怎么用

MCP 工具：先 `change_set_create`，再对每个页面调用 `change_set_add_page`，写上完整的新内容和它基于的版本。`change_set_get` 会说明现在还缺什么。

命令行：

```bash
pandocs commit --change-set "把退货期限改成 30 天"
```

所有改动，包括新页面和带 `--delete` 的删除，都会放进一个变更集，等人来合并。
